# 1.3.0 升级与回退

1.3.0 可以读取原有主配置和旧 AUTO+USER 节点文件。节点成功启动并保存快照后，会将自动生成内容移到 `.runtime/nodes/`，`nodes/node_<ID>.conf` 保留用户覆盖项及注释。当前**没有自动配置备份或一键配置回退功能**。

## 升级前备份

先停止需要升级的实例或容器，备份完整实例配置目录，而不是只备份 `heki.conf`。备份应包含 `nodes/`、证书、路由、DNS、规则和已有运行记录；通过软链接或绝对路径引用的目录外文件另行备份。容器还应保留原 Compose 文件、环境配置及镜像版本。

以下仅示例默认 `/etc/heki` 目录的备份。命名实例和自定义 `-c` 路径使用各自实际目录；多个实例共用程序时，应一起安排停机与更新。备份包含面板密钥和证书私钥，放在仅管理员可访问的位置。

```bash
sudo install -d -m 700 /root/heki-backups
sudo tar -C /etc -czf "/root/heki-backups/heki-before-1.3.0-$(date +%Y%m%d-%H%M%S).tar.gz" heki
```

确认备份能列出主配置和节点文件后，安装脚本用户执行 `heki update 1.3.0`。Docker 使用 `hekicore/heki:1.3.0` 或 `latest`，拉取镜像后重新创建容器；只重启原容器不会更新程序。

## 升级后检查

- 查看各节点启动日志和实际协议、端口，并用原客户端验证 TCP/UDP 连接。
- 管理脚本用户可运行 `heki node list` 和 `heki config --effective`；后者显示本次成功启动时的配置及来源，不是实时监控。
- 节点配置更改需要重启所属实例/容器；Docker 环境变量更改需要重建容器。

旧主配置不因节点文件迁移而被改写；原有节点参数与注释保留。节点覆盖仅接受支持的参数，具体范围见 [主副配置说明](heki/heki-config.md)。

## 回退 1.2.9 的限制

| 情况 | 1.2.9 的行为 |
|---|---|
| 原有受支持的节点参数 | 新版保存时使用旧版识别的完整中文 USER 标记，旧版通常可继续读取；成功启动后会重新写入 AUTO 区 |
| 停用节点文件 | 旧版启动成功后会删除不在 `node_id` 列表里的节点文件；1.3.0 的保留行为不会在旧版继续生效 |
| 历史协议提示 | 旧版不读 `.runtime/nodes/`，会回到主配置和面板探测；混合协议节点需复核选中的协议 |
| 新增节点参数 | 节点 VMess 认证参数、`CF_*`、Hy2 ECH 等新增覆盖项不受旧版支持；保存了文字不代表功能生效 |
| 简化 USER 标记 | 旧版不识别单独的 `[USER]` 或 `# [USER]`。若尚未由 1.3.0 成功保存成完整中文标记，旧版可能忽略其后的参数，并在回写时丢失它们 |
| 超长配置行 | 1.3.0 接受最长 1 MiB 的行；旧版约 64 KiB 上限会使主配置读取报错，节点读取则可能截断并在回写时丢失后续内容 |

完整兼容标记为：

```ini
# ---- [USER] 用户自定义（修改这里，重启保留）----
```

## 需要回退时

1. 停止受影响的所有实例/容器，另存当前 1.3.0 配置和日志供排查。
2. 恢复升级前备份的完整配置，保留原备份供再次恢复。不要把 `.runtime` 快照直接覆盖为用户配置。
3. 切换到对应的 1.2.9 安装包或镜像，恢复原环境配置。`heki update 1.2.9` 的安装流程可能自动启动默认实例，所以应在执行前完成配置恢复。
4. 启动后核验每个节点的协议、端口和客户端连通性。旧版不生成新版 `--effective` 记录，应以当前启动日志为准。

1.2.9 曾多次同版本重发；保留原安装包校验值或镜像 digest，便于确认实际回退到哪一份产物。没有升级前备份时，不应把“只换回旧二进制或镜像标签”当作无损回退。
